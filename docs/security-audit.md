# Security audit — Pack 2 (2026-11-12, branch `review-prep`)

Method: read-only queries against the **live** Supabase project (policies,
grants, every function body via `pg_get_functiondef`, triggers, Realtime,
storage, cron), the Edge Function sources and deployed JWT settings, the
Flutter `lib/`, `ios/`, `android/`, `pubspec`, and git history. New SQL was
tested on the live project **inside a transaction that always rolls back**
(the pattern Packs 1–6 used, approved by the owner). No emulator, no device.
Emails / phones / keys are never printed here.

Status: **Fixed** = code/SQL written and tested here · **Applied** = also live
· **Needs owner** = a dashboard step, secret or decision · **Won't fix** = why given.

## Checked and fine (evidence on live, 2026-11-12)

- **RLS on every one of the 39 tables in `public`.** No `USING (true)` on private data; `orders` / `delivery_groups` "hide unpaid" are RESTRICTIVE.
- **Roles** come from `profiles.role` (protected by `guard_profile_privileged_columns`: role, tier, points, phone, referral fields, …), checked by `is_admin()` / `is_rider()` / `is_super_admin()`; never from `user_metadata`. Riders are created only by `admin-create-rider` (admin JWT + `is_admin`). No profile UPDATE policy exists, so balances/tiers move only in definer functions.
- **Wallet:** no client write policy on `wallets` / `wallet_transactions`; `credit_wallet` service-only with a unique reference; every debit locks the wallet row (`for update`) and checks the balance in the same transaction; no negative balances on live.
- **Checkout:** `create_paid_delivery_order` / `_pickup_` / `_errand` / `_gift_` price every line from `products`, reject other-vendor / unavailable / out-of-range quantities, run `_check_leg_style` (fixed-menu: no packs, ≤20/item, style must match), take an idempotency key with an advisory lock, check the PIN (returned, counted), lock the wallet. Delivery fee = location price × brackets, server-side.
- **Riders:** 3-job cap enforced inside `accept_order` / `accept_delivery_group` under a per-rider advisory lock; `for update nowait` on the job; only the assigned rider sets the price / verifies delivery.
- **Cancel:** `student_cancel_delivery_group` refuses once `rider_id` is set; no refund (business rule).
- **Every admin / rider RPC gates on the role** (sweep of all 30+).
- **Realtime:** published tables all have RLS; riders get no row access to `orders` / `delivery_groups` (they use `rider_job_signals` + RPCs).
- **Storage:** one bucket `product-images` (public read; admin-only write; 5 MB; jpeg/png/webp).
- **Edge Functions:** `paystack-webhook` HMAC-SHA512 over the raw body before parsing, constant-time compare; `verify-paystack-payment` / `create-virtual-account` / `admin-create-rider` verify the user JWT themselves; `push-notification` / `send-notification` / `birthday-rewards` require the service or trigger key; `signup` / `phone-otp` rate-limit in Postgres; Termii and Paystack secrets only in function secrets.
